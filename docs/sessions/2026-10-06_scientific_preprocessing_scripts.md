# 科研脚本与集群资源约定调整

## 用户要求与决策

- 全部 sbatch 仅使用 `q_fat_c`，fMRIPrep 默认每被试 6 个 CPU，控制 FreeSurfer 等步骤的并发内存压力。
- fMRIPrep／XCP-D 的命令与参数选择直接写在作业脚本中，便于科研人员分析逻辑，不封装到 `src/`。
- 延续 THU／XY 独立输入、仅静息态、无 session 目录、至少 2 个合格 run 及既有结果路径。

## 修改

- 配置与四份 sbatch 使用 `q_fat_c`；fMRIPrep 的脚本资源和直接 Bash 执行默认值均为 6 个 CPU，其他阶段为 1。
- 两份容器脚本按路径读取、显式分析命令、离线环境检查、输入审计、运行、产物审计的顺序执行。
  `--nprocs` 对应实际 Slurm CPU 配额，嵌套线程限制为 1。
- 从 `src/imaging/pipeline.py` 移除容器命令构建；保留清单、提交、上下游审计和运行记录。
  `src/imaging/config.py` 只导出共享路径和配置值，实际回归、滤波及输出选项均能在 sbatch 中直接阅读。
- 同步 AGENTS、README、ARCHITECTURE、集群手册和影像方法说明。此前会话记录中的双分区默认值已由本次约定替代。

## 验证

- 本地 Python 3.12.9、Git Bash 下执行 14 项合成科学验证，包含两份真实 Bash 入口的命令预览、
  模拟容器运行、产物审计与运行记录，以及失败重跑不保留完成记录、释放锁的验证。
- 对四份 sbatch 执行 Bash 语法检查，并检查 Git 差异与临时产物清理。
- 未连接集群或运行真实容器；正式批量计算前仍需在集群提交少量真实被试检查内存与产物。
- 未修改正式输入、衍生数据或分析结果，也未配置数据同步。
